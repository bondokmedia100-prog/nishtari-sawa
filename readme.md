# نشتري سوا

تطبيق Expo للموبايل بواجهة مصرية، وخادم API بـ Node.js 22 وFastify، وقاعدة PostgreSQL/PostGIS. يعرض الخادم الصفقات النشطة ضمن 1–3 كم من موقع المستخدم من دون كشف عنوان قائد المجموعة.

## النسخة المنشورة

- عنوان API: https://nishtari-sawa.onrender.com
- معاينة ويب قابلة للتجربة: https://nishtari-sawa-preview.pages.bu.app/
- `GET /` يعرض تعريفًا بالخدمة وروابطها.
- `GET /health` يفحص اتصال الخادم بقاعدة البيانات.
- `GET /api/v1/deals/nearby?lat=30.0444&lng=31.2357&radius_km=2` يعرض صفقات القاهرة التجريبية.
- `GET /api/v1/config` يعرض مفاتيح تشغيل المنصة العامة دون بيانات حسابات.
- ترحيلات قاعدة البيانات والبذور تعمل تلقائيًا عند بدء الخادم، مع سجل يمنع إعادة تطبيقها؛ ترحيل `006_commerce_operations.sql` يضيف المخزون والتسليم والطلبات وإعدادات المنصة.

## الحسابات والواجهات

مصدر الخادم في هذه الحزمة يدعم البريد وكلمة المرور للمشتري والبائع، ورمز وصول صلاحيته 7 أيام، وصفحة إدارة محمية. تُخزّن كلمات المرور كقيم مشتقة بـ scrypt ولا تُعاد إلى الواجهة. أسماء الأدوار في قاعدة البيانات: `buyer` و`supplier` و`admin`؛ واجهة البائع تقابل `supplier`.

- `POST /api/v1/auth/register` ينشئ حساب مشتري أو بائع. كلمة المرور يجب أن تكون من 12 إلى 128 حرفًا.
- `POST /api/v1/auth/login` و`GET /api/v1/auth/me` للدخول والتحقق من الجلسة.
- `GET /api/v1/seller/deals` و`POST /api/v1/seller/deals` لإدارة عروض البائع ومخزون كل عرض؛ العروض الجديدة تنتظر موافقة الإدارة.
- `GET /api/v1/seller/orders` و`PATCH /api/v1/seller/orders/:membershipId/fulfillment` لمتابعة طلبات البائع وتحديث حالة التسليم ورقم التتبع.
- `GET /api/v1/me/memberships` و`DELETE /api/v1/me/memberships/:membershipId` لمجموعات المشتري وطلباته.
- `GET /api/v1/admin/dashboard` و`GET /api/v1/admin/orders` و`GET/PATCH /api/v1/admin/settings` و`PATCH /api/v1/admin/deals/:dealId` و`PATCH /api/v1/admin/users/:userId` للوحة الإدارة. إيقاف آخر حساب أدمن أو الحساب المستخدم حاليًا مرفوض.
- الانضمام يقبل كميات من 1 إلى 1,000,000، ويقارنها بالمخزون الفعلي وسقف العرض والكمية المحجوزة، مع منع تكرار انضمام الحساب نفسه.
- يختار المشتري الشحن من التاجر أو الاستلام الذاتي؛ الشحن يتطلب عنوانًا، وتحديث حالة «تم الشحن» يتطلب رقم تتبع أو رابطًا آمنًا.
- مفاتيح الإدارة تتحكم بتسجيل المشترين والبائعين، وإضافة العروض، والطلبات، والشحن، والاستلام الذاتي، ووضع الصيانة. القيود مطبقة على الخادم أيضًا.
- تُحفظ نقطة الاستلام على كل عرض، حتى لا يؤدي تغيير موقع عرض جديد إلى تحريك العروض القديمة.

الملف المستقل المرافق `nishtari-sawa-full-app.html` هو واجهة الويب، وتطبيق Expo يدعم حسابات المشتري والانضمام بكمية يحددها المستخدم. إدارة عروض البائع ولوحة الإدارة عبر الويب. يجب نشر نسخة الخادم مع ترحيل `006_commerce_operations.sql` قبل استخدام المخزون والشحن والتتبع. التحديث المحلي وحده لا يغيّر الخدمة المنشورة أو صفحة المعاينة.

## تهيئة حساب الإدارة

عيّن `ADMIN_SETUP_TOKEN` في إعدادات Render إلى سر عشوائي لا يقل عن 32 حرفًا. ثم أرسل طلبًا واحدًا إلى `POST /api/v1/auth/bootstrap-admin` يتضمن `setupCode` و`name` و`email` و`password`. لا تضع الرمز في ملفات عامة أو في الواجهة. بعد إنشاء أول حساب إدارة، يرفض الخادم إنشاء أدمن آخر من هذا المسار.

## حدود الإطلاق

- الصفقات الحالية بيانات تجريبية في القاهرة وليست عروضًا حقيقية. استخدم عنوان شحن تجريبيًا فقط في المعاينة؛ العنوان يُحفظ لعرضه للمشتري والبائع والإدارة.
- Google وApple والتحقق من البريد أو OTP غير موصولة. استخدم الدخول بالبريد فقط.
- الدفع الإلكتروني غير موصول. تسجيل الانضمام لا يخصم مالًا، لكنه يحجز الكمية من المتاح حتى إلغاء الطلب من المشتري أو الإدارة.
- أوقف الخادم الحسابات غير النشطة فورًا في كل طلب محمي. يلزم إعداد سياسة خصوصية واحتفاظ وحذف للبيانات، ودعم ومراقبة ونسخ احتياطية قبل إطلاق تجاري.

## تشغيل تطبيق Expo

عنوان الخادم موجود في `mobile/.env.example`، والملف المحلي `mobile/.env` غير مضاف إلى Git. لتشغيل التطبيق:

1. ثبّت Node.js ثم شغّل `npm install` داخل `mobile/`.
2. شغّل `npx expo start` داخل `mobile/` وافتح المشروع باستخدام Expo Go.
3. اسمح للتطبيق باستخدام الموقع حتى يعرض الصفقات القريبة. تسجيل المشتري بالبريد وكلمة المرور يستخدم واجهة API نفسها، بينما إدارة عروض البائع والأدمن تتم عبر الويب.

إذا أردت تشغيل API محليًا، انسخ `mobile/.env.example` إلى `mobile/.env` ثم غيّر العنوان إلى IP الكمبيوتر على شبكة Wi-Fi نفسها، مثل `http://192.168.1.20:3000`؛ لا تستخدم `localhost` على الهاتف.

## تشغيل الخادم محليًا

1. انسخ `.env.example` إلى `.env` وضع كلمة مرور محلية عشوائية من أحرف وأرقام فقط لـ PostgreSQL، وسرًا عشوائيًا لـ `JWT_SECRET` و`ADMIN_SETUP_TOKEN` بطول 32 حرفًا على الأقل. لا ترفع ملف `.env` إلى Git.
2. شغّل `docker compose up --build` من مجلد المشروع. ينشئ PostGIS قاعدة محلية، ويطبّق الخادم ملفات SQL تلقائيًا.
3. افحص `http://localhost:3000/health`.

لا تستخدم إعدادات `.env.example` أو كلمات مرور محلية كأسرار إنتاج. متغيرا `DATABASE_URL` و`JWT_SECRET` في Render محفوظان ضمن إعدادات الخدمة فقط؛ أضف `ADMIN_SETUP_TOKEN` سرًا عند نشر تحديث الحسابات.

## حالة المنتج وحدوده

- الصفقات والموردون الحاليون بيانات تجريبية في القاهرة، وليست عروضًا حقيقية.
- ترحيل بيانات العرض يمدد صفقات القاهرة التجريبية 90 يومًا بعد كل تحديث للخادم.
- حسابات البريد وكلمة المرور متاحة على الخدمة؛ إعدادات تشغيل المخزون والشحن تتطلب نشر ترحيل `006_commerce_operations.sql`.
- الدفع الإلكتروني وEscrow غير موصولين؛ طلب الانضمام لا يخصم أموالًا.
- صفحة المعاينة تعرض صفقات API التجريبية؛ المنتجات والكميات والأسعار بيانات تدريبية وليست عروضًا حقيقية.
- طلبات المعاينة تحفظ الكمية وطريقة التسليم للتجربة فقط ولا تخصم أموالًا؛ استخدم عنوان شحن تجريبيًا ولا تنفذ شحنات حقيقية.
- لا تنفّذ مشتريات حقيقية قبل اختيار مزود هوية وOTP ومزود دفع ملائم لمصر، وتحديد سياسة الاسترداد والامتثال.
- خطة Render المجانية قد توقف الخادم بعد الخمول، فيتأخر أول طلب. قاعدة البيانات المجانية الحالية معروضة للانتهاء في 1 نوفمبر 2026.
- يلزم قبل الإطلاق التجاري استبدال البيانات التجريبية، وإضافة مراقبة ونسخ احتياطية وسياسة خصوصية واستضافة دائمة.
